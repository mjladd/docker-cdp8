## Phase 1: foundation crates

| WP | State | Notes |
|---|---|---|
| 1.1 `cdp-sf` | in progress | First slice: reads and writes plain WAVE files (`fmt `+`data`+`PEAK`), 16-bit PCM and 32-bit float only. Reads (does not yet write) the `cue `/`LIST`/`adtl`/`note`/`sfif` named-property block. Every on-disk layout (fmt chunk incl. WAVE_FORMAT_EXTENSIBLE sub-format GUIDs, PEAK chunk, property block hex encoding) was read from `legacy/dev/newsfsys/sfsys.c`/`props.c`, not guessed. Verified three ways: 17 unit tests (property codec, PEAK codec, fmt parsing, write/read round trip); 2 integration tests against real files with expected values computed independently (Python, not this crate's own code) and cross-checked against `legacy` `sndinfo props`; and a scan of all 553 `.wav` files in `docs/manual/sounds` (100% open and decode without error), with a random sample of 10 cross-checked field-by-field against `legacy` `sndinfo props` (all matched). Not yet done: AIFF/AIFC, PVOC-EX, WAVE_FORMAT_EXTENSIBLE multichannel decoding, the CDP-derived file types (analysis/pitch/transposition/formant/envelope), writing the property block, and sample types other than 16-bit PCM and float32 (`Int32`/`Int2424`/`Int2432`/`Int2024`/`Masked` are detected in `FmtInfo` but not yet decoded to samples). |
| 1.2 `cdp-data` | in progress | First slice: breakpoint files only (parsing, range validation with the exact legacy error text, and evaluation). Two evaluators: `interpolate` (binary search, always correct regardless of query order) and `interpolate_from_cursor` (a faithful port of `read_value_from_brktable` in `legacy/dev/cdp2k/tklib3.c`, the function actually used everywhere -- not the similarly-named `interp_val` in `readdata.c`, which turned out to be dead code, never called from any program in this codebase, discovered by checking call sites before porting it). The number tokenizer (`get_float_from_within_string` in `tklib1.c`) is ported byte-for-byte, including real quirks: no scientific notation, and one invalid character invalidates the whole token and abandons the rest of the line. One of these quirks was cross-checked against a real run of `legacy` `modify loudness` with a crafted file containing `1e-5`, which fails with "Data not paired correctly" -- confirming an initial, incorrect assumption (that partial digits before the invalid character survive) was wrong, before it shipped. Also ported: both real dB-to-gain conversions in the codebase, `convert_dB_at_or_below_zero_to_gain` (attenuation only, errors on a positive value) and the more general `dbtogain` (allows boost). 22 unit tests. Not yet done: mix files, texture note-data files, tuning files, and plain number lists. |
